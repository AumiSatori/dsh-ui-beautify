# 客户端构建与本机同步

## 启动失败的原因

2026-10-24 23:48:49，同步新增了 `DcbLens.createChatDisclosureMotion(...)` 调用，配套 bundle 到 23:49:08 才完成构建。23:48:59 的 DSH 启动正好读入中间版本，导致 `dsh-ui-beautify` 未激活并阻止桌面启动。普通语法检查无法发现“函数调用存在、对应导出尚未更新”的错误。

修复后的 `scripts/build-lens.mjs` 在写入前校验 JavaScript 语法、bundle 标记、外围用到的所有导出及函数类型，并检查编译期间读取的源码和客户端是否被其他任务修改。发布时先保存原文件为 `client.js.bak-<随机 ID>`，在同一目录写完并刷新临时文件，再重命名替换 `client.js`。旧文件不会先清空；替换失败时保留原客户端。构建锁阻止同时发布，发现已有锁时应检查对应 PID，不擅自删锁。

## 正确的接入顺序

1. 独立目录开发并验证。先记录当前运行文件、备份以及文件归属，保留其他任务的改动。
2. 把本次外围 `client.js` 差异应用到**运行目录外**的一份最新客户端副本，例如集合目录 `.scratch/<任务>/client.next.js`。这份副本必须基于当前运行版，不可直接用旧开发版整文件覆盖。
3. 将本次源码差异合入运行目录，包括新增模块、导出和依赖；此时实际 `client.js` 仍是完整旧版，不包含新调用。
4. 在运行目录执行：

   ```powershell
   node scripts/build-lens.mjs --template="D:\workspace\dsh-project\.scratch\本次任务\client.next.js"
   ```

   构建完成、所有校验通过后，一次替换为新 bundle 与新外围调用匹配的客户端。模板、任一源码或运行客户端在构建中变化会终止，重新核对并发差异后再接入。
5. 执行 `npm run check:lens`、相关回归和实际 DSH 页面验证；必要时使用项目统一重启脚本。不要在未构建的调用已经进入运行目录时重启。

只改 bundle 内部源码、没有外围调用差异时，可直接运行 `npm run build:lens`。`npm run check:lens` 只检查，不发布。不要用其他同步脚本直接先写 `client.js` 再另行构建，也不要复制未验证的构建文件或原地截断运行客户端。

此流程只改构建和同步机制，不清理偏好、聊天、导入素材，不自动提交、推送、合并、打标签或发版。
