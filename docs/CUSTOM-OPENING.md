# 自定义开屏

设置 → dsh-UI美化 → 全局布局 → 开屏欢迎。

- **默认 · Logo 字符填充**：使用宿主的 Harness 鲸鱼 Logo 轮廓，以真实字符填充并逐行显现。可修改填充字符和速度。没有图片底层，完成后不保留绘制循环；旧版书写模式会自动迁移到这里。
- **自定义代码**：像 HTML 自定义背景一样，粘贴代码或导入单文件 HTML、CSS、JavaScript。导入后可先预览，点击“应用代码开屏”才保存。代码和动图素材各自保存，切换类型或恢复默认不删除素材。
- **动图 / 短视频**：保留现有 GIF、APNG、WebP、MP4、WebM 播放方式。

明暗主题分别记忆开屏类型、素材、代码、速度、铺放与开关；旧的单套偏好会先沿用到两种主题。媒体按版本保存在本机，切换主题或替换日间素材不会覆盖夜间素材。

开屏欢迎、全图背景和用户消息气泡均并列显示日间（浅色）与夜间（深色）的配置名称、启用状态，并分别标记“当前主题”“编辑中”和“当前使用”。气泡的编辑标签只影响预览和编辑目标，聊天仍使用宿主当前主题对应的样式。

定时代码与交互代码独立保存，连同日夜主题共四个位置。切换结束方式时恢复该位置的代码，已编辑但尚未应用的草稿在设置页内分别保留；点击“应用代码开屏”才持久保存。旧版本的共用代码只迁入升级前选中的结束方式，另一种保持空白。普通配置仅保存引用，代码仍放在 IndexedDB；替换一份不会清掉其他三份。

## 本机代码开屏历史

保存并应用过的代码开屏会登记到“本机开屏历史”，来源只保存在当前浏览器的 IndexedDB；点击历史卡片即可快速切换，并保留其他主题与交互代码。它不会写进普通设置，也不会替换另一主题的代码引用。

本机代码历史只显示用户自己保存的条目，插件不会自动添加私有示例。切换浏览器来源或设备前，可在“全局配置”中导出包含本机素材的完整备份。

## 手势交互开屏

在“自定义代码”内先选择结束方式，再编辑代码。“交互完成后结束”模式的操作栏提供“手势开屏示例”，连接至少 4 个点，再重复绘制确认。图案会生成到代码编辑器中，点击“应用代码开屏”才保存；日夜两套仍分别保存。手势是交互开屏的示例，也可以自行编写或导入其他交互。选择“定时结束”时隐藏手势入口、录制区和说明，保留已保存的代码。鼠标、触屏和键盘均可操作，跨过未选择的中间点会自动连上。

交互模式等待代码主动调用 `window.dshWelcomeDone()`，不会到达播放秒数或旧的 30 秒兜底后自动消失。错误图案提示后可重试，正确图案淡出进入聊天；外层“跳过”和 iframe 内外的 Esc 均可退出。手势仅用于可跳过的开屏体验，不提供身份认证或安全锁。

## 代码文件约定

文件不超过 2MB。HTML 可以包含内嵌 CSS 与 JavaScript；单独的 CSS 或 JavaScript 会被包成 HTML 文档。图片、字体、视频与第三方库需内嵌，不能引用外部网址、相邻文件、CDN、Node.js、DSH 服务接口或模块入口。

渲染区域等于当前窗口可用区域（排除桌面标题栏）。使用 `vw`、`vh`、`clamp()`、弹性布局或 Canvas 的 `innerWidth` / `innerHeight` 随窗口变化。文件本身写死的像素坐标不会自动转换为响应式布局。

代码完成时可调用：

```js
window.dshWelcomeDone()
```

默认“定时结束”模式下，不调用也会按设置的最长播放时长（3–15 秒）退场。选择“交互完成后结束”则等待交互主动结束。播放完成后由美化插件淡出并衔接原生界面；按 Escape 或点击“跳过”随时退出。资源加载失败、代码出错或素材缺失时回到默认字符 Logo。减少动态效果与强制颜色下不运行开屏。

隔离页面的 `html[data-theme]` 为 `light` 或 `dark`，并提供 `--dsh-welcome-background`、`--dsh-welcome-foreground` CSS 变量。模板可据此适配黑白主题；用户自定义的固定颜色仍需在代码中使用这些变量或主题选择器。

代码存储在单独的本机 IndexedDB，不写入普通设置，不与背景库混用。只在明确播放预览或启动时创建隔离 iframe；不允许读取宿主 DOM、存储或网络。预览完成、停止、切分类、隐藏页面、关闭设置或卸载时移除 iframe、消息监听和计时器。

## 与参考项目的关系

[LeeRolling/dsh-chat-wallpaper](https://github.com/LeeRolling/dsh-chat-wallpaper) 提供“开机动画 → 全屏视频 → 淡出 → 聊天背景”的衔接。该项目本身不是通用代码开屏加载器，其客户端入口依赖 DSH ModuleLoader、服务端接口，以及另一插件的离场信号，不能把 `lib/client.js` 直接导入为开屏文件。

仓库演示中“点击按钮 / Enter 继续”的五步开屏来自它引用的 [6shenhonghong9/dsh-startup-screen](https://github.com/6shenhonghong9/dsh-startup-screen)。这类状态机、按钮和键盘交互可以写成独立 HTML，在本插件的交互模式中运行，最后调用 `window.dshWelcomeDone()`。原项目访问宿主、外部音视频和其他插件 DOM 的部分需要改写，素材需内嵌。当前只核对实现，没有安装、导入或套用上述项目的代码与素材；具体接入等待用户明确指令。

使用美化插件自己的生命周期。若同时启用其他全屏开屏插件，仍可能产生叠层与时序冲突，应只让一套插件管理开屏。

## 在 Loading plugins 之前显示开屏

Desktop 的 `Loading plugins…` 早于普通客户端插件。仅在美化插件启动后隐藏它，会留下之前的等待画面。提前引导补丁在原生前端的 body 末尾插入本插件独立构建的启动器：从同一份本机设置和 IndexedDB 读取开屏，正常插件随后接管同一个控制器与 iframe，不重复播放。开屏结束早于宿主加载完成时保留最后画面，接管后退场；插件加载失败时恢复原生错误信息。关闭开屏或减少动态效果时保留原生启动流程。

这是本机 Desktop 前端补丁，插件升级后可通过本机补丁库重打。`scripts/early-opening-patch.mjs --asar <app.asar> --apply` 只允许在 Desktop 完全退出时写入，保留整包备份并更新被修改 index 的完整性信息；`--when-closed` 等待退出后应用一次。退出后的 `data/dsh-ui-beautify/early-opening/status.json` 中 `state: installed` 才表示已落盘，下次启动生效。应用运行时不直接修改安装包，也不自动关闭用户窗口。

## 验证

`node test/welcome-code-browser.mjs` 检查字符 Logo 与真实宿主轮廓、字符中间帧、文件导入和本机持久化、独立背景状态、预览结束资源释放、宿主与网络隔离、误发完成消息、代码错误回退、窗口缩放、明暗/窄屏/键盘焦点和减少动态效果。默认字符、媒体播放、恢复默认与完整客户端构建另有回归。

`npm run test:theme-gesture` 检查三处主题状态标注、气泡编辑与实际主题的区分、手势录入与保存、超过旧 30 秒时限后的交互、错误重试、正确退场、键盘与跳过，并输出隔离页面截图。桌面实际体验由用户验收。
