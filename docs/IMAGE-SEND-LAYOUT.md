# 图片加载占位与发送滚动边界

本次处理用户消息附件加载后突然撑大正文的问题。实际页面使用订阅适配器的 `codexImageThumb`，其单图高度为 auto，图片宽高没有输出到 DOM；从占位字符切到真实图片时会改变框高，即使附件元数据完整也会发生。另一个原生分支通常已按附件宽高预留空间；但持久附件缺少宽高时，计算产生无效尺寸，浏览器丢弃内联宽高，只剩约 44px 的按钮，合成横图解码后增到 902px。进入原生尾部跟随后，这些变化同时改变滚动范围和可见正文位置。

`src/message-image-layout.js` 为订阅适配器的用户消息单图固定 240px 方形预览框，使用 contain 完整显示横图、竖图和极端比例图片，允许留边。原生分支仅提供宿主已有的 240px 未知尺寸后备占位，有效内联尺寸仍优先。两者都不覆盖原图查看器、编辑器缩略图、工具输出和 Markdown 插图。图片子元素允许收缩，避免极长图片的网格最小内容尺寸溢出。无需观察图片地址、读取附件内容、额外加载图片或启动常驻绘图循环；样式随插件样式表卸载。

`test/image-send-layout-browser.mjs` 从测试者指定的 `DSH_ASAR` 提取已安装组件，使用合成附件和延迟图片，覆盖横图、竖图、极端比例、小图、缺失尺寸，以及短正文、滚动边界、两秒后才加载和暗色窄屏。9 组中，加载前后的框尺寸、正文滚动范围、滚动位置和图片在视口中的位置一致。

`test/image-adapter-layout-browser.mjs` 从 `DSH_CODEX_CLIENT` 提取实际安装的订阅图片组件，另覆盖 10 组同类布局、64px 多图缩略图、乐观预览转持久附件、失败重试及原图打开回调。加载与确认转换前后位置稳定，原点击行为保留。所有画面和附件均为合成内容。

同时将 `test/send-motion-coordination-browser.mjs` 扩展到 9 组：原有单行、多行、延迟提交、暗色窄屏，加短正文、正文从不溢出到溢出、图片发送时附件栏移除与输入栏收缩，以及原生滚动方向反转。`test/send-motion-smooth-browser.mjs` 再用宿主 `ScrollFollow` 的 smooth 滚动、连续追加和滚动范围重定向复现真实节奏。新增保护只在没有布局收缩的大幅反向时交还宿主，避免重新播放反向 280ms 补间；多行输入收缩的小幅负向差量仍由当前补偿接续。9 组协调回归和 smooth 回归通过。此前 `src/composer-scroll-motion.js` 的协调修复保持不变。本次用户纠正后的边界是：正文未超过聊天可视区时流畅，超过后开始滚动时抖动。
