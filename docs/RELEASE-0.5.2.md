# dsh-UI美化 0.5.2

本版以 0.5.1 为基线，修复启动后与切换会话后首次回车发送仍会出现的跳动，并收录 0.5.1 之后已合入主分支的三项改进。不改变已有偏好，升级保留导入素材。

## 回车发送

- 切换会话后的首次发送，宿主每渲染一行（运行状态、本轮过程、正式用户消息）会占用主线程 150–230ms。期间正文仍在合成器上滑动，插件重新计算时却按长任务之前的位置起步，把已经滑过的距离重放一遍，画面整体下跳 28–52px。现在续接正在运行的弹簧时，取位置与起步使用同一帧时刻，直接接上屏幕当前画面。
- 启动后首次发送，宿主偶尔先移除回显的用户消息，约 50ms 后才插入正式行，贴底时对话先落一行再弹回。现在这段空档里插件在原位放一个不可交互、对读屏隐藏的占位副本，正式行到达或 1.5s 后移除；滚动位置被夹住时一并补回。
- 回显消息被替换为正式行时，新行加入相邻行的同一条滑动，不再单独起步错开；新一轮带入场位移的状态行也获得补偿（补偿改用合成器上的 `transform`，与宿主的 `translate` 入场叠加）。

## 收录的其他改进

- 页头“…”中“下载 Session 日志 / 反馈”菜单补上开合动画。
- 任务面板新增任务进度、输出文件、工具记录三个独立模块开关；右上角状态简化为“处理中 / 查看成果 / 空闲”。
- “输入栏外观”新增上拉菜单透明度，独立控制 `@` 文件选择与命令建议面板底色。

## 检查

实际执行记录见 [validation-0.5.2.json](validation-0.5.2.json)：JavaScript 语法、客户端从发布源码重新构建、Node 回归、发送协调与输入栏 / 消息动效的浏览器合成回归，以及安装包内容检查。发送协调回归新增 `stream-echo-gap`、`stream-long-task` 两个场景，修复前分别出现反向 2 次与长任务后停滑 0px，修复后均通过。

开发实测：桌面端（本机临时调试端口、屏幕实际画面录制）启动后首次与第二次发送不再出现大幅单帧位移（修复前 +38px / +12px）；Web 端 `localhost:8442` 切换会话后首次发送，宿主长任务 147–172ms 期间正文单向移动、无反向，结束后无占位或动画残留。长任务续接修复之后未再做桌面端录制，用户在桌面端反馈已明显顺滑。详细过程见 [发送动效协调](SEND-MOTION-COORDINATION.md)。

已有版本、标签及发布产物保持不变。
