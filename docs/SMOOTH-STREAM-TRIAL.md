# 连续流式优化开发记录

开发分支：`work/smooth-stream-opt`。基线为 `v0.4.6` 加上原工作副本的已有改动快照。早期修订称为「试用 1 / 试用 2」；在获得整合发版授权后，相关调整纳入 `v0.5.0`，发布说明和检查记录以 [RELEASE-0.5.0.md](RELEASE-0.5.0.md) 为准。

在「对话布局 → 对话动效 → 流式文字渐显」中切换 **连续流式优化**。默认开启；关闭后即时使用原有吐字节奏和滚动路径，无需重新载入页面；文字缩短及资源清理修复仍共用。总开关关闭、减少动态效果和强制颜色仍沿用原有行为。

## 本次变化

- 新文字到达时重定位文字范围；单纯渐显的帧复用尾部测量，仅更新新放出的一段与尚未显示的部分，减少重复遍历和 Range 更新。
- 吐字采用积压压力曲线，小批文字的基础速度由旧模式的每秒 40 字提升到每秒 90 字，并保留有界追赶与速度过渡，减少短句拖尾；优先按完整字素处理表情与组合字符，没有 `Intl.Segmenter` 时按 Unicode 码点退化处理。
- 积压超过预算时直接显示，文本缩短时清除旧动画，已结束的范围及时释放，避免积压的显示层遮住已到达内容。
- 可见消息行的布局读数在一次更新内复用，并在替换动画前保存位置；流式滚动采用连续的临界阻尼轨迹，重新跟随时携带有界速度，未发生变化的轨迹直接复用。
- 修订 2 处理了原先「回答行超过视口 1.5 倍高度就放弃整次补偿」的分支。长回答改用互不嵌套的可见内容块，最多 48 个绘制目标、192 次访问及 400 万物理像素面积预算；大段代码、表格、媒体、思考块等不可安全拆分的内容继续使用原生滚动，不会为一整条长回答创建巨大绘制层。
- 仍由宿主控制消息内容、Markdown、真实滚动位置和滚动范围。本次不接管模型流、思考正文、工具调用或卡片渲染，也不向 `scrollTop` 写入试用跟随位置。

参考了 [dsh-smooth-stream](https://github.com/Laplace-bit/dsh-smooth-stream) 的分阶段调度与连续跟随思路。本次使用现有美化模块实现，没有引入该插件或新增运行依赖。

## 主人验收建议

文字预览现在使用固定的输入节奏，方便切换试用开关后重新播放同一组文字。该预览只对照文字效果，不模拟聊天滚动。短回答没有溢出屏幕时，本来也不会发生滚动；滚动对照需使用超过一屏、正在生成且跟随底部的普通长回答。

用同一段输出切换试用开关对照：持续短句、一次到达长段、长代码块与表格、表情、思考结束后的折叠、工具调用和卡片、手动向上翻阅、切换会话，以及关闭渐显后的直接显示。重点观察新文字是否完整、手动阅读是否被打断、卡片及复制操作是否正常。

本次只进行必要的语法、构建及导出一致性检查；功能、性能与视觉体验由主人自行验证。当前不作“无功能影响”或性能提升幅度的验收结论。

关闭优化是即时效果对照。`scripts/stream-trial.ps1` 仅用于早期独立试用目录的接线记录，不作为正式版本安装器；正常安装或检查使用 `scripts/profile.mjs`。完整版本回退应选择已发布的旧版包或对应源码，不清除原有偏好和导入素材。
