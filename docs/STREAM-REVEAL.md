# 流式文字渐显

设置位置：对话布局 → 对话动效 →「流式文字渐显」。默认开启，强度默认「轻柔」，另有「标准」「明显」。

## 现象

宿主 Markdown 在流式时复用已完成的块，只重渲染尾块；React 每次用 `nodeValue = 完整字符串` 更新文本。上游按 token 推送时新字一个个硬跳出，按大块推送时（实测一次 100–1300 字）整段同时出现。

## 实现

`src/stream-reveal.js`，效果参照桌面聊天客户端的流式输出：

- 只处理主页面原生对话：`[data-chat-flow]` 里 `[data-chat-flow-kind^="assistant"]`、`[data-chat-group-part="reasoning"]` 行内的 Markdown。DS Bot 是另一个插件，它的气泡（`.bt-msg`、`.bt-bubble`、`.bt-astack`）即使挂在原生行上也完全不处理。
- 第一次看到的内容（历史、切换会话）不重播。例外：对话已稳定显示 800ms 以上时，底部新插入的一两条回答（回答行带着首块文字一起出现）也从开头打出；上方分页加载的历史和一次插入多行的会话加载仍直接显示。
- 新增文字通过 CSS Custom Highlight API（`::highlight(dcb-stream-0…9)`）绘制，不包裹、不替换 React 的文本节点，不触发重排。
- **平滑打字**：刚到达的文字先隐藏进待显示队列，一个帧时钟按自适应速度从队首逐字放出：速度 = 积压字数 / 跟随延迟（轻柔 260ms、标准 340ms、明显 440ms），下限 40 字/秒、上限 4000 字/秒。稳定输出时显示位置均匀地落后到达位置约一个延迟；模型一次吐出一大段时先快后慢地追上，不会整段跳出。超过 6000 字的单次到达直接显示。
- 每帧放出的一小段作为一个片段淡入（180/240/320ms，10 级墨色缓出上升，带少量同色微光模拟模糊消散），形成跟在光标后面的柔和渐变边缘。
- React 整值替换会让 live Range 塌缩，所以片段按字符偏移保存，每帧只从末尾回溯仍在动画中的尾部重新定位。
- 帧时钟只在有待显示文字或淡入片段时运行，结束即停；窗口隐藏或帧暂停超过预算时直接全部显示。
- `prefers-reduced-motion` / `forced-colors`、关闭开关和卸载都会取消片段，移除 highlight 与样式，文字直接显示。

## 跟随滚动平滑（`src/composer-scroll-motion.js`）

流式输出时宿主每多一行就把 `scrollTop` 一帧跳 24–64px（实测间隔 100–300ms），整段文字一顿一顿往上蹦。开启「流式文字渐显」后，同一个发送滚动补偿模块也接管流式跟随：

- 发送时建立观察器（排在宿主跟随控制器之后，同帧补偿），回合仍在生成时持续保留，思考阶段也不过期；没有发送意图时，第一次跟随跳动也会接管后续跳动。
- 每次跳动用 280ms 缓动从当前画面平移到真实位置，文字从下往上连续滑动，不改滚动范围也不写 `scrollTop`。
- 回合结束时宿主同帧删除运行状态行、在回答上方插入「已完成，用时」标题、追加回合尾栏。流式补偿按行记录内容坐标，标题把下方各行推下去的那段位移也一起补偿；收缩与增长连续发生时并入同一条缓动，不再放弃补偿。
- 滚轮、触摸、指针和阅读按键立刻交还宿主，之后 1.2 秒内不再接管；只有向下的跟随跳动才会接管，往上翻看（包括思考期间）永远不被补偿。减少动态效果或关闭「流式文字渐显」时不接管。
- DS Bot 的聊天界面（含 `.bt-msg` 等气泡）不接管流式跟随，发送时的原有补偿不变。

无头 Chrome 实测（本机 8442，满帧）：流式期间文字以缓动连续上移，单帧峰值约 10–15px；回合结束前后 1.5 秒内没有任何超过 0.3px 的跳动。

## 验证

- `node --test test/*.test.mjs`、`node test/stream-reveal-browser.mjs`（11 项：逐 token 隐藏后打出且不碰 React 文本节点、整段从开头均匀打出并在约一秒内放完、代码与表格自上而下、无常驻帧循环、历史不重播、用户行与 DS Bot 气泡不处理、首块到达也打出、减少动态效果与强制颜色、开关与强度、卸载）。
- 跟随滚动：`DSH_ASAR=… node test/composer-scroll-motion-browser.mjs`（发送补偿 7 项）与本机 8442 的无头 Chrome 实测（见上节）。
